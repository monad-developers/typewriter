# Submit mutations

How a mutation gets from a user's key to the runtime — signing typed data on
the client, submitting it to the server, and following it through the lifecycle.

Documentation is under construction — this is a placeholder page. Content will
be filled in over the coming iterations.
:::

## Planned contents

- Building and signing the EIP-712 typed data on the client against
  `typewriter.domain`
- Replay protection: nonces, deadlines, and scope
- Session keys and bootstrap mutations
- Submitting a signed mutation with `typewriter.execute`
- Reading `TypewriterMutationResult` and handling rejected mutations

  included → safe → finalized
