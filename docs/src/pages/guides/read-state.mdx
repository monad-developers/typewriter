# Read application state

Typewriter gives you three ways to read a running app: the live `typewriter.state` proxy, the generated `typewriter.schema` Drizzle tables, and the `typewriter.on` event stream.

## Read current state with `typewriter.state`

`typewriter.state` is a typed, read-only proxy over your contract's storage. It maps your Solidity `struct State` onto its storage layout slots directly, so the contract needs no `public` getters or `view` functions — Solidity visibility does not affect what the proxy can reach.

Field accesses return promises. Mappings are indexed by key.

```ts
// Read a single account's balance.
const balance = await typewriter.state.accounts[accountId].balance; // bigint
```

Reads resolve against the runtime's local, revm-backed mirror of storage rather than issuing an `eth_call` to the chain. This means `typewriter.state` reflects locally accepted state, which can be ahead of what is included or finalized onchain.

For the full TypeScript type of the proxy, see [TypeScript reference](/reference/typescript).

## Query mutation history with `typewriter.schema`

The runtime generates and migrates one Drizzle table per Solidity `Mutation` enum member. Each table is named `<name>_mutations`, where `<name>` is the mutation name lowercased — `Mutation.Transfer` becomes `transfer_mutations`, `Mutation.MarketOrder` becomes `marketorder_mutations`.

Every table includes the same lifecycle columns (`id`, `status`, `blockNumber`, `transactionHash`, and so on) followed by one column per field in the mutation struct and one prefixed `signature_` column per field in your `Signature` struct.

Pass a table from `typewriter.schema` to a Drizzle client to query:

```ts
import { desc } from "drizzle-orm";

// Fetch the 20 most recently accepted transfer mutations.
const recent = await db
  .select()
  .from(typewriter.schema.transfer_mutations)
  .orderBy(desc(typewriter.schema.transfer_mutations.id))
  .limit(20);
```

A row is written when a mutation is accepted and updated as it advances through the lifecycle. Mutations that are received but not accepted are not written to these tables.

For the full column schema and ABI-to-Postgres type mapping, see [TypeScript reference](/reference/typescript).

## Stream updates with `typewriter.on`

`typewriter.on` returns an unsubscribe function. Subscribe to the `"block"` event to run a callback each time a submitted block reaches a confirmation depth:

```ts
const unsubscribe = typewriter.on("block", (block) => {
  console.log(block.status, block.number, block.transactionHash);
});
```

`block.status` is one of `"included"`, `"safe"`, or `"finalized"`. Under FIFO sequencing the event carries a `mutations` array; under batch sequencing it carries a `batches` array instead.

If your app uses batch sequencing, subscribe to `"batch"` to receive each batch as it changes status, before the containing block event fires:

```ts
const unsubscribe = typewriter.on("batch", (batch) => {
  console.log(batch.status, batch.id, batch.mutations.length);
});
```

For the full event payload types — including the `"mutation"` event that fires on every individual lifecycle change — see [TypeScript reference](/reference/typescript).
