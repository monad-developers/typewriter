# Project structure

A Typewriter app has three top-level directories: `contracts/`, `src/`, and `frontend/`. The `token` example app, which this guide uses as a reference, lives at `apps/token/` in the repository.

```
apps/token/
├── contracts/          # Solidity source and build output
│   ├── foundry.toml
│   └── src/
│       ├── Token.sol
│       ├── Token.sol.d.ts
│       ├── Transfer.sol
│       └── Mint.sol
├── src/                # Bun server
│   └── index.ts
└── frontend/           # Browser client
    ├── App.tsx
    ├── frontend.tsx
    └── index.html
```

## `contracts/`

The `contracts/` directory holds all Solidity source files and is built with Foundry. The `foundry.toml` configuration enables the `storageLayout` extra output, which Typewriter reads at startup:

```toml
[profile.default]
src = "src"
out = "out"
libs = ["../node_modules", "node_modules"]
extra_output = ["storageLayout"]
```

The source files under `contracts/src/` define three things:

- **The `State` struct** — the single Solidity struct that contains all application state. In the token example, `State` holds a `totalSupply` and a mapping of `Account` structs keyed by address.
- **Mutation libraries** — one Solidity library per mutation (for example, `Transfer.sol` and `Mint.sol`). Each library defines the mutation struct, its EIP-712 typehash and hash function, its signature verifier, and its state-transition function. See [State and mutations](/guides/state-and-mutations) for how to write them.
- **The entrypoint contract** — `Token.sol`, which inherits from `typewriter/Typewriter.sol`, declares the `Mutation` enum, and implements the `dispatch` function that routes each mutation to its library.

## `src/`

`src/index.ts` is the Bun server entry point. It imports `createTypewriter` from the `typewriter` package and the compiled entrypoint contract, starts the runtime, then registers HTTP routes.

```ts
import { createTypewriter } from "typewriter";
import Token from "../contracts/src/Token.sol";

const typewriter = await createTypewriter(Token, {
  address: requireEnv("TOKEN_ADDRESS") as Address,
  account: scheduler,
  chainId: Number(requireEnv("CHAIN_ID")),
  rpcUrl: requireEnv("RPC_URL"),
  database: { url: requireEnv("DATABASE_URL"), maxConnections: 25 },
  sequencing: { order: "batch", batchOrder: ["Mint", "Transfer"] },
});
```

`createTypewriter` returns the `typewriter` handle, which the routes use to submit mutations (`typewriter.execute`), read state (`typewriter.state`), expose the EIP-712 domain (`typewriter.domain`), and subscribe to lifecycle events (`typewriter.on`). See [API endpoints](/guides/api-endpoints) for the full route list and [Configuration](/guides/configuration) for all `TypewriterConfig` fields.

## `frontend/`

`frontend/App.tsx` is a React component that runs in the browser. It fetches the EIP-712 domain from `/api/domain`, constructs and signs mutation payloads using viem's `signTypedData`, posts them to `/api`, then opens an `EventSource` connection to `/api/mutation/:id/status` to stream the mutation's lifecycle status as it advances from `accepted` through to `finalized`.

## How the Solidity entrypoint is imported

`Token.sol` is imported directly as a TypeScript module:

```ts
import Token from "../contracts/src/Token.sol";
```

Bun resolves this import through a type declaration shim, `Token.sol.d.ts`, that is generated by Typewriter and lives alongside the Solidity file:

```ts
// Generated by typewriter from Token.sol. Do not edit by hand.
declare const entrypoint: import("typewriter").TypewriterSolidityEntrypoint<{
  readonly storageLayout: { ... };
  readonly mutations: {
    readonly Transfer: { readonly tag: 0; readonly params: [...] };
    readonly Mint:     { readonly tag: 1; readonly params: [...] };
  };
  readonly signature: [...];
}>;
export default entrypoint;
```

At startup, `createTypewriter` runs `forge build` on the entrypoint and reads the compiled output from `contracts/out/`. From that output it derives:

- **Mutation tags** — the `uint8` values that correspond to each `Mutation` enum member.
- **Mutation params** — the ABI parameter names and types for each mutation struct, used to build the Drizzle schema tables and type-check `typewriter.execute` calls.
- **Signature params** — the ABI parameter names and types for the `Signature` struct, also written as columns in the schema tables.
- **Typed storage** — the storage layout that backs `typewriter.state`, giving the runtime a typed, slot-level mirror of the contract's state without requiring public Solidity getters.

## Environment and configuration

Copy `.env.example` to `.env` and fill in the five required variables before starting the server:

| Variable | Purpose |
| --- | --- |
| `RPC_URL` | JSON-RPC endpoint for the target chain |
| `DATABASE_URL` | Postgres connection string |
| `CHAIN_ID` | Chain ID used for EIP-712 typed-data signing |
| `TOKEN_ADDRESS` | Address of the deployed `Token` contract |
| `PRIVATE_KEY` | Private key for the scheduler account that submits onchain transactions |

See [Configuration](/guides/configuration) for all available runtime options.
