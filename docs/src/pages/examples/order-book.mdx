# Order Book

The order-book app is a complete example built on Typewriter. It shows how to configure custom batch sequencing across multiple order types, bootstrap accounts with WebAuthn passkeys, delegate signing to ephemeral session keys, and settle trades onchain. The source is at [apps/order-book](https://github.com/monad-exp/typewriter/tree/main/apps/order-book).

## What the app demonstrates

The app covers the main Typewriter capabilities in one place:

- **Custom batch sequencing.** The server defines a `batchOrder` that controls which mutation types are processed first within each settled batch. See [Batch sequencing](#batch-sequencing) below.
- **WebAuthn account bootstrap.** New users register a passkey. The resulting credential public key becomes the account's root key.
- **Session keys.** After registration, an ephemeral P-256 key pair is generated in the browser and stored in IndexedDB. Subsequent mutations are signed with the session key rather than prompting the user for a passkey on every action.
- **Deposits and withdrawals.** Users transfer ERC-20 assets into the contract and withdraw them back out, with balance tracked per account in contract state.
- **Onchain settlement.** The Bun server sequences mutations locally for fast confirmations, then submits settled batches to the `OrderBook` contract on chain.

## App structure

The workspace lives under `apps/order-book` and is divided as follows:

| Directory | Contents |
|---|---|
| `contracts/src/` | Solidity mutations and the `OrderBook` contract |
| `src/` | Bun server: state model, mutation config, HTTP routes, persistence hooks |
| `frontend/` | React UI served by the Bun process |
| `sdk/` | Shared EIP-712 types, ABI, and constants (aliased as `order-book-sdk`) |
| `scripts/` | Participant scripts that drive the HTTP API |

## Mutation set

Each mutation is a Solidity library in `contracts/src/`. The `OrderBook` contract (in `contracts/src/OrderBook.sol`) dispatches to these libraries from its `dispatch` function. The ten mutations are:

| Mutation | File | What it does |
|---|---|---|
| `Initialize` | `Initialize.sol` | Creates an account, sets the root key, and registers the first session key |
| `Authorize` | `Authorize.sol` | Adds a new key to an existing account |
| `Revoke` | `Revoke.sol` | Removes a key from an account |
| `AddInstrument` | `AddInstrument.sol` | Registers a trading pair (base asset, quote asset, lot sizes) |
| `Deposit` | `Deposit.sol` | Credits an ERC-20 balance to an account |
| `Withdrawal` | `Withdrawal.sol` | Debits an ERC-20 balance and transfers it back to the user |
| `LimitOrder` | `LimitOrder.sol` | Places a resting order at a specific price |
| `MarketOrder` | `MarketOrder.sol` | Fills against the best available resting orders |
| `ChangeOrder` | `ChangeOrder.sol` | Reprices an existing resting order |
| `CloseOrder` | `CloseOrder.sol` | Cancels a resting order and releases locked funds |

All mutations except `Initialize` use EIP-712 typed-data signing. Nonces are parallel and keyed by `(account, keyIndex)`, so concurrent mutations do not serialize.

## Batch sequencing

The server exports `ORDER_BOOK_BATCH_ORDER` from `src/app.ts`. This array controls the order in which mutation types are processed within each settled batch:

```ts
export const ORDER_BOOK_BATCH_ORDER = [
  "Initialize",
  "Authorize",
  "Revoke",
  "CloseOrder",
  "ChangeOrder",
  "LimitOrder",
  "MarketOrder",
  "AddInstrument",
  "Deposit",
  "Withdrawal",
] as const;
```

Within a batch, cancels (`CloseOrder`, `ChangeOrder`) run before new orders (`LimitOrder`, `MarketOrder`). This ensures that a user who cancels and replaces an order in the same batch does not have both orders live simultaneously. For background on how Typewriter uses the batch order, see [Configuration](/guides/configuration).

## Account bootstrap and session keys

The app supports two sign-up paths, both defined in `frontend/hooks/`.

**WebAuthn sign-up (`useSignUp.ts`).** The frontend calls the WebAuthn `create` API to register a passkey. The resulting credential public key is hashed with `keccak256` to produce a 32-byte account ID. The app then submits an `Initialize` mutation carrying:

- `rootPublicKey`: the WebAuthn credential public key (`rootKeyType: 1`)
- `publicKey`: a freshly generated P-256 session key (`keyType: 0`)

The session key is stored in IndexedDB. All subsequent mutations are signed with it using `crypto.subtle.sign`.

**Demo sign-up (`useDemoSignUp.ts`).** For local testing, the frontend generates a random Ethereum private key as the root key (`rootKeyType: 2`) and follows the same `Initialize` flow. No browser passkey prompt is shown.

In both paths the `Initialize` signature carries `rawSignature: "0x"` — account creation is self-certifying because the contract verifies that `keccak256(rootPublicKey) == account`. After initialization the account holds two keys: key 0 (the root key, full permissions) and key 1 (the session key, delegated permissions). For more on the account model and key types, see [Concepts](/concepts).

## Running the app locally

Follow the general local setup in [Get started](/guides/get-started), then run these commands from three separate terminals:

```bash
anvil --block-time 0.4
```

```bash
cd apps/order-book && cp .env.example.local .env && bun run deploy
```

```bash
cd apps/order-book && bun dev
```

Open `http://localhost:3000`. The same Bun process serves the API, the React frontend, and the Typewriter runtime.

### Environment variables

The app reads its configuration from a single `apps/order-book/.env` file. The required variables are:

| Variable | Description |
|---|---|
| `PRIVATE_KEY` | Funded deployer/backend wallet private key |
| `DATABASE_URL` | Postgres connection string |
| `ORDER_BOOK_ADDRESS` | Deployed `OrderBook` contract address |
| `RPC_URL` | RPC endpoint; accepts comma-separated failover URLs |
| `CHAIN_ID` | Chain ID (`31337` for Anvil, `10143` for Monad testnet) |
| `BUN_PUBLIC_RP_ID` | WebAuthn relying party ID (usually the hostname) |
| `BUN_PUBLIC_ORIGIN` | Expected WebAuthn origin |
| `API_URL` | Running order-book backend URL (used by participant scripts) |

For Monad testnet or a hosted deployment, copy `apps/order-book/.env.example.testnet` instead.
