# `storage-layout`

TypeScript types and utilities for Solidity's [`storageLayout`](https://docs.soliditylang.org/en/v0.8.33/internals/layout_in_storage.html#storage-layout).

This library allows for inspecting / decoding **public or private** contract variables of [smart contracts](https://ethereum.org/developers/docs/smart-contracts/) written in the [Solidity programming language](https://www.soliditylang.org). It infers TypeScript types for autocomplete and strict type checking.

```ts
import { getStorageSlot, decodeStorageVariable } from "storage-layout";

const storageLayout = { storage: [ /** ... */ ], types: { /** ... */ } } as const;

const [slot] = getStorageSlot(storageLayout, "totalSupply");
const totalSupply = decodeStorageVariable(storageLayout, "totalSupply", { [slot]: "0xa" }); // 10n
```

`storage-layout` does not depend on an RPC client. Compose it with any client
that can read raw storage slots:

```ts
import {
  type AccountStorage,
  decodeStorageVariable,
  getStorageSlot,
  type ConcreteStorageVariable,
  type StorageLayout,
} from "storage-layout";
import type { Address, PublicClient } from "viem";

async function readContractStorage<
  const layout extends StorageLayout,
  const variable extends ConcreteStorageVariable<layout>,
>(
  client: PublicClient,
  layout: layout,
  address: Address,
  variable: variable,
) {
  const slots = getStorageSlot(layout, variable);
  const values = await Promise.all(
    slots.map((slot) => client.getStorageAt({ address, slot })),
  );
  const storage = Object.fromEntries(
    slots.map((slot, index) => [slot, values[index]!]),
  ) as AccountStorage;

  return decodeStorageVariable(layout, variable, storage);
}

const balance = await readContractStorage(
  publicClient,
  storageLayout,
  "0x1111111111111111111111111111111111111111",
  "balances[0x2222222222222222222222222222222222222222]",
);
```

## Solidity `storageLayout`

The `storageLayout`, is a less common, opt-in `solc` compiler output that documents the layout of Solidity variables in EVM storage.

`storageLayout` can be generated by foundry in two ways:
- By CLI flag: `forge build --extra-output storageLayout`
- By `foundry.toml` option: `extra_output = ["storageLayout"]`

## Storage variables

A storage variable is a Solidity variable access path rooted at a contract state variable. It can refer to a top-level variable or to a concrete sub-value inside a struct, array, or mapping. Visibility does not matter: `public`, `internal`, and `private` state variables all appear in `storageLayout` and can be inspected if you can read the contract's raw storage.

For this Solidity contract:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Example {
    struct Metadata {
        uint64 lastUpdate;
        bool active;
    }

    uint256 public totalSupply;
    address private owner;
    Metadata internal metadata;
    mapping(address account => uint256 balance) private balances;
    uint128[3] private fixedNumbers;
    uint256[] private dynamicNumbers;
}
```

Valid storage variable paths include:

```ts
totalSupply;
owner;
metadata;
metadata.lastUpdate;
metadata.active;
balances[0x1111111111111111111111111111111111111234];
fixedNumbers;
fixedNumbers[1];
dynamicNumbers;
dynamicNumbers[0];
```

The selector syntax is intentionally close to Solidity expression syntax: `.` selects a struct field, and `[...]` selects an array element or mapping value. Many functions in this package accept this shape as a parameter.

## Solidity type support

Supported Solidity storage types:

- `bool`
- `uint<M>` and `uint`
- `int<M>` and `int`
- `address`
- `bytes<M>`
- enums
- structs
- fixed arrays
- dynamic arrays
- mappings
- `bytes` and `string`, including short in-slot and long out-of-slot storage forms
- nested combinations of supported types

Unsupported types fail loudly instead of decoding approximately:

- `fixed<M>x<N>` and `ufixed<M>x<N>` fixed-point decimals
- internal and external function types
- contract, interface, and library types
- user-defined value types
- `bytes` and `string` mapping keys

Not applicable to this package:

- Constants and immutables, because they are not ordinary account storage entries.
- Transient storage, because it is separate from persistent contract storage.

## API reference

### `getStorageSlot`

Computes the EVM storage slots for a storage variable.

```ts
function getStorageSlot(layout: StorageLayout, variable: StorageVariable): Hex[];
```

The result is always an array. Single-slot variables return a one-element array. Composite variables that span multiple slots return every unique slot.

Examples:

```ts
const [ownerSlot] = getStorageSlot(layout, "owner");
const metadataSlots = getStorageSlot(layout, "metadata");
const [balanceSlot] = getStorageSlot(layout, `balances[${account}]`);
```

Dynamic array roots resolve to the array length slot. Indexed dynamic array variables resolve to element slots.

### `getStorageVariable`

Matches a raw storage slot back to the storage variables that could have been affected by that slot.

```ts
function getStorageVariable(
  layout: StorageLayout,
  slot: Hex,
  knownVariables?: readonly StorageVariable[],
): StorageVariable[];
```

Packed fields can produce multiple matches because multiple Solidity values can share one EVM slot. Composite variables in `knownVariables` expand to their leaf variables when matching.

```ts
const variables = getStorageVariable(layout, changedSlot);
```

Mapping slots are not reversible from a slot alone because Solidity hashes mapping keys into slot addresses. Pass concrete keyed mapping variables as `knownVariables` when you want keyed mapping slots included in the match set.

```ts
const variables = getStorageVariable(layout, changedSlot, [
  `balances[${account}]`,
]);
```

If the layout contains a mapping and `slot` does not match any reversible static variable, `getStorageVariable` throws. Pass the relevant keyed mapping variables in `knownVariables` to resolve those slots, or accept that mapping slots without a known key cannot be recovered.

### `decodeStorageVariable`

Decodes one concrete leaf storage variable from raw account storage.

```ts
function decodeStorageVariable(
  layout: StorageLayout,
  variable: ConcreteStorageVariable,
  storage: AccountStorage,
): unknown;
```

The `storage` object is keyed by slot and contains raw slot values. The requested variable must point to one concrete value, not a composite struct, fixed array root, dynamic array root, or unkeyed mapping.

```ts
const owner = decodeStorageVariable(layout, "owner", {
  [ownerSlot]: "0x0000000000000000000000001111111111111111111111111111111111111234",
});
```

For long `bytes` and `string` values, `storage` must include both the root length slot and the required payload slots.

### `encodeStorageVariable`

Encodes one concrete leaf storage variable into masked slot writes.

```ts
function encodeStorageVariable(
  layout: StorageLayout,
  variable: ConcreteStorageVariable,
  value: unknown,
): SlotWrites;
```

The return value is keyed by slot. Each write contains a `value` and `mask` so packed fields can be updated without overwriting neighboring fields in the same slot.
Short `bytes` and `string` values produce one root-slot write. Long values produce the root length-marker write plus payload-slot writes.

```ts
const writes = encodeStorageVariable(layout, "paused", false);
const nextSlot = applySlotWrite(writes[pausedSlot], existingSlotValue);
```

### `decodeStorageDiff`

Decodes a sparse raw slot diff into a sparse storage-variable diff.

```ts
function decodeStorageDiff(
  layout: StorageLayout,
  storageSlotDiff: StorageSlotDiff,
  knownVariables?: StorageVariable[],
): StorageVariableDiff;
```

`StorageSlotDiff` mirrors geth prestate tracer diff mode: `pre` and `post` are sparse objects keyed by raw storage slot. A slot present on only one side is decoded against zero on the missing side.

Mapping slots are not reversible from a slot alone because Solidity hashes mapping keys into slot addresses. Pass concrete keyed mapping variables as `knownVariables` when you want keyed mapping diffs included in the decode result.

```ts
const diff = decodeStorageDiff(layout, slotDiff, [
  `balances[${account}]`,
]);
```

For long `bytes` and `string` values, the diff must contain both the root length slot and every changed payload slot. A real sparse revm/geth diff that contains only changed payload slots and omits the unchanged root length slot is not enough to recover the decoded value, and `decodeStorageDiff` throws rather than returning a partial decode.

### `encodeStorageDiff`

Encodes a sparse storage-variable diff into sparse masked slot-write diffs.

```ts
function encodeStorageDiff(
  layout: StorageLayout,
  storageVariableDiff: StorageVariableDiff,
): StorageSlotWriteDiff;
```

Missing variables mean unchanged values. The result keeps per-slot `value` and `mask` so packed fields can be merged without overwriting neighboring fields.

```ts
const diff = encodeStorageDiff(layout, {
  pre: { owner: oldOwner, paused: false },
  post: { owner: newOwner, paused: true },
});
```

If two variables in the same diff produce writes that disagree on overlapping bits of the same slot — for example, two packed fields whose pre/post values cannot be merged into a single masked write — `encodeStorageDiff` throws rather than silently dropping one side.

### `createStorageProxy`

Creates a lazy, read-only JavaScript object projection over contract storage.

```ts
function createStorageProxy<
  layout extends StorageLayout,
  getSlots extends
    | ((slots: Hex[]) => AccountStorage)
    | ((slots: Hex[]) => Promise<AccountStorage>),
>(
  layout: layout,
  getSlots: getSlots,
  knownVariables?: StorageVariable[],
): StorageProxy<layout, getSlots extends (slots: Hex[]) => Promise<AccountStorage> ? true : false>;
```

Leaf reads call `getSlots` with only the slots required for that variable. If `getSlots` is async, leaf reads return promises. Composite reads return sub-proxies.

```ts
const state = createStorageProxy(layout, async (slots) => {
  return readStorage(slots);
});

const owner = await state.owner;
const balance = await state.balances[account];
```

Pass `knownVariables` to make mapping keys enumerable through `Object.keys`. Direct keyed reads do not require `knownVariables`.

### `applySlotWrite`

Applies one masked slot write to an existing 32-byte slot value.

```ts
function applySlotWrite(slotWrite: SlotWrite, existingSlot: Hex): Hex;
```

Use this when applying an `encodeStorageVariable` or `encodeStorageDiff` result to a raw storage value.

```ts
const nextSlot = applySlotWrite(write, existingSlotValue);
```
